## FreeLLMAPI – Access Free AI Models With Automatic Switching

**Channel:** TheNextNewThingAI (@TheNextNewThingAI)
**Link:** https://www.youtube.com/watch?v=DKsra7jn8jQ

FreeLLMAPI pulls together free AI models from different providers and automatically switches between them when free credits run out, so work keeps going without a paid plan. The video's example is paying $200 a month for Claude even though not every task needs a top-tier model. For builders watching their AI bills creep up, routing everyday work to free tiers is a concrete way to push costs back down.

## Running a 120B model offline on Surface RTX Spark Dev Box with Intelligent Terminal

**Channel:** Microsoft Developer (@MicrosoftDeveloper)
**Link:** https://www.youtube.com/watch?v=L1b4AI_CPeA

A 120-billion-parameter model runs entirely locally on a Surface Laptop Ultra, using its NVIDIA RTX Spark chip with 128 GB of unified memory and a feature called Intelligent Terminal. The demo shows the machine doing complex work like writing new agent skills, with all context handled on-device and nothing going to the cloud. That matters for privacy, for working offline or in secure environments, and for latency — a frontier-class model that never leaves your laptop.

## Automation vs Physical AI

**Channel:** Microsoft Developer (@MicrosoftDeveloper)
**Link:** https://www.youtube.com/watch?v=1lX4bK3FTPk

Automation repeats a task; physical AI gets smarter every time it runs. That is the distinction from Michael MacKenzie, Microsoft's VP of Product Management for Azure IoT and Digital Operations. Automation does the same thing the same way forever, while physical AI in factories, warehouses, and machines learns from each run and improves. The test for what gets sold as AI is simple: does the system get better the more it runs, or does it just repeat?

## Customize your agent from a Chat Window?

**Channel:** Microsoft Developer (@MicrosoftDeveloper)
**Link:** https://www.youtube.com/watch?v=FVYDyA1LcGI

Using the Microsoft Foundry model catalog, you can find the best model for a specific use case, swap only the model deployment, and run the same evaluation over both options, capturing real cost and latency from real runs. The video argues the biggest model is quietly the wrong one more often than you would think. Turning model selection from a vibes-based decision into a measured one is unglamorous advice that saves real money.
